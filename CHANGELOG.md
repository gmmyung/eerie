# Changelog

## 0.7.0 - 2026-10-25

Released with `eerie-sys 0.5.0`; uses IREE 3.13.0.

### Added

- Automatic compiler discovery from the active Python environment, with `Compiler::with_library` for custom installations and `library_path` / `api_version` for inspection. Building the compiler feature no longer requires an installed compiler library.
- Optional `cross-lang-lto` for the runtime on Linux and macOS, with a matching Nix toolchain and application linker setup guide.
- Melior coexistence with the stock compiler wheel on macOS through an explicit application export setting. Linux and macOS CI cover both initialization orders, debug/release builds, and VMVX/LLVM CPU compilation.
- Compiler API documentation on docs.rs.

### Changed

- Compiler handles share process-wide initialization and can be created, cloned, and dropped independently.
- Raw compiler bindings expose an `eerie_sys::compiler::IreeCompiler` API table instead of linker-resolved free functions.
- Native runtime drivers follow Cargo features; Vulkan is compiled only when enabled. Math/libc shims are restricted to bare-metal targets, and dependencies are enabled only by the features that use them.
- Native C/C++ builds no longer translate extra Rust codegen flags. Cross-language LTO is selected explicitly by its feature.
- Remove obsolete compiler configuration and unused wrappers, and trim packaged native sources.

### Fixed

- Match the Windows runtime's CRT to Rust for debug/release and `crt-static` builds, eliminating LNK4098.
- Return recoverable compiler discovery, incompatible API, and missing-symbol errors, allowing retries after failed loading.
- Prefer the compiler's own LLVM/MLIR symbols on glibc Linux to avoid Melior collisions.
- Respect compiler callback byte lengths and free status-message storage when formatting fails.

### Upgrading from 0.6

- Remove IREE-specific rpath settings from `RUSTFLAGS` and `.cargo/config.toml`. Install `iree-base-compiler==3.13.0`; discovery uses Python on PATH or `EERIE_PYTHON`.
- Raw binding users must load and initialize an `IreeCompiler` table and retain it for the lifetime of every compiler object created through it.
- For Melior on macOS, apply the [application build setting](README.md#using-melior-on-macos). It hides executable exports; applications with a host plugin API need a different export policy.

## 0.6.1 - 2026-10-24

Published with `eerie-sys 0.4.1`.

### Added

- Added Windows x64 MSVC compiler/runtime support and CI coverage, including automatic compiler import-library generation for the PyPI wheel.
- Added tag-triggered crates.io publishing with full CI validation, dependency ordering, and source-verified retries using `CARGO_REGISTRY_TOKEN`.
- Added `Compiler::compile_file`, `compile_str`, and `compile_bytes` for compiling directly to owned VMFB archives with per-call flags.
- Added `Function::invoke_one` for a single typed output, with result-count validation before invocation.
- Added `BufferView::read_into` for reusing host storage, plus allocation-free `rank`, `element_count`, and `byte_length` metadata queries.

### Changed

- Share one retained VM context and module set across resolved functions, removing repeated module-vector allocation and redundant program-owned module handles.
- Consolidated compiler/runtime bindgen configuration and shared CMake defaults for hosted and embedded builds.
- Simplified README, ResNet, and integration-test compilation paths using the convenience APIs.

### Fixed

- Initialize the compiler's process-argument query with real arguments and cache its result, fixing a Windows null-pointer crash and empty results on Unix.
- Give compiler file outputs their own descriptor so destroying an output preserves the caller's Rust file; support Windows CRT descriptors and Unicode output paths.
- Validate global compiler command-line arguments before consuming the one-time initialization slot, allowing a valid retry after an interior-NUL error.

## 0.6.0 - 2026-10-24

### Changed

- Updated IREE from 3.11.0 to 3.13.0 (`89ece87b89852100c0a4ac3d515e14842d090967`) and aligned compiler wheels, CI, and the Nix development shell.
- Updated device creation for proactor pools and shared frontier trackers. Each hosted runtime retains one device group across all its loaded programs.
- Migrated bare-metal execution to inline HAL, preserving the high-level runtime and typed buffer APIs. Embedded `local-sync` selection now uses inline HAL and requires inline VMFBs.
- Rebuilt the runtime fixtures for HAL module ABI 0.7. Users must recompile VMFBs generated by IREE 3.11 or earlier.
- Updated `eerie-sys` to 0.4.0 with the updated raw C API, a unified native archive containing inline modules, generated ISA headers in bindgen, and removal of obsolete printf linkage.
- Isolated Nix compiler environments by IREE version and fail immediately if compiler discovery fails.
- Protected VM argument/result list creation and destruction against concurrent driver initialization, which can temporarily reset IREE's process-global builtin type adapters.

### Added

- Added `Driver::local_inline()` and `DeviceSpec::local_inline()` for inline VMVX and embedded ELF execution on hosted and bare-metal targets.
- Added repeatable fixture generation and regression coverage for internal 64-bit VM calls, device selectors, failed device creation, multiple programs, retained-object lifetimes, and overflowing or empty shapes.
- Added a standalone Cortex-M4 Rust executable and QEMU test, plus Linux/macOS and bare-metal CI jobs.

### Compatibility

- Vulkan requires version 1.3 with timeline semaphores, scalar block layout, and synchronization2.
- CUDA `sm_89` targets default to PTX 8.4 and require CUDA 12.4 driver support unless target features are overridden.
- The hosted `Runtime -> Program -> Function` API is preserved. Bare-metal full-HAL artifacts must be rebuilt using inline execution.

## 0.5.0 - 2026-06-26

### Added

- Added `runtime::DeviceSpec`, `runtime::Driver`, and `runtime::DeviceInfo` for explicit runtime device selection and device queries.
- Added optional runtime `f16` and `bf16` buffer view support behind the `half` feature.

### Changed

- Reworked the safe runtime surface around `Runtime -> Program -> Function` so users load VMFB modules, resolve functions, pass typed `BufferView<T>` inputs, and receive dynamically typed `Value` outputs.
- Moved low-level VM/HAL assembly APIs behind the crate-private runtime implementation; public runtime usage now goes through the safe high-level API.
- Use a retained process-global VM instance for hosted runtime setup to avoid concurrent HAL type registration hazards in IREE's low-level initialization path.
- Treat macOS Vulkan as unsupported in eerie; use the Metal backend on macOS.

### Notes

- Published `eerie-sys` `0.3.3` with the new optional `vulkan` feature.

## 0.4.3 - 2026-06-22

### Added

- Added safe `BufferView<bool>` support for IREE Bool8 tensors, including host buffer creation, writes, reads, read mappings, VM ref extraction, and runtime invocation paths.
- Added Bool8 validation when reading bool buffer contents so invalid byte values cannot become invalid Rust `bool` values.

### Notes

- Raw-compatible numeric buffer element types keep their existing direct host transfer and zero-copy read mapping paths.
- `eerie-sys` remains at `0.3.2`; Bool8 constants were already available in the generated raw bindings.

## 0.4.1 - 2026-06-21

### Fixed

- Map Rust signed integer `BufferView<T>` element types to IREE signless integer HAL element types (`Int8`/`Int16`/`Int32`/`Int64`) so MLIR `i*` tensor ABIs round-trip correctly through typed buffer views.

### Notes

- `eerie-sys` remains at `0.3.2`; this patch only changes the safe wrapper crate.

## 0.4.0 - 2026-06-18

### Changed

- Removed the redundant `runtime::hal::Tensor<T>` wrapper. Use `runtime::hal::BufferView<T>` directly for typed HAL buffer views.
- Removed `runtime::vm::Function::invoke_tensors`. Build VM `List` arguments explicitly with `BufferView<T>::to_ref`, call `Function::invoke`, then read `Ref<BufferView<T>>` outputs.
- Updated runtime tests, README snippets, and examples to use `BufferView<T>` as the single typed runtime tensor/buffer abstraction.

### Notes

- `eerie-sys` remains at `0.3.2`; this release only changes the safe wrapper crate API.

## 0.3.3 - 2026-06-15

- Removed runtime test serialization and added stale-instance/concurrent-invocation regression coverage.

### Notes

- `eerie-sys` remains at `0.3.1`; this patch only changes the safe wrapper crate.

## 0.3.1 - 2026-06-15

## 0.3.0 - 2026-06-15

Pinned IREE version:

- IREE submodule: `v3.11.0`
- IREE submodule commit: `e4a3b0405d7d23554da26403658d0e8c3c5ecf25`
- Compiler wheel used by CI/docs.rs fallback: `iree-base-compiler==3.11.0`

### Changed

- Reworked the runtime bindings around lower-level VM/HAL objects and removed the old high-level runtime API wrapper.
- Moved runtime objects to retained/released ownership where the IREE C API supports reference counting, reducing unnecessary Rust lifetime coupling.
- Expanded HAL and VM coverage, including first-class buffer view/tensor handling, device queries, bytecode modules, function invocation, list handling, and additional reflection helpers.
- Updated examples and tests to use the new runtime API directly.
- Added a Nix flake/devshell for local development.

### Added

- Added embedded `no_std` runtime support for `target_os = "none"`.
- Added a Rust-backed C ABI support path using `tinyrlibc`, `libm` wrappers, compiler builtins, and a small critical-section-backed synchronization shim.
- Added local bare-metal `pthread.h`/`thread.h` compatibility headers for IREE's generic synchronization fallback.
- Added tests for newly exposed compiler/runtime API paths.
- Added a checked-in VMVX test fixture for runtime tests.

### Fixed

- Pinned CI to `iree-base-compiler==3.11.0` so the linked `libIREECompiler` matches the generated bindings.
- Updated GitHub Actions checkout to `actions/checkout@v6.0.3` for Node 24 compatibility.
- Removed obsolete no-std `_fini` and `end` linker stubs after verifying the Rust-based embedded path no longer needs them.

### Notes

- Hosted runtime builds use IREE's default runtime HAL driver selection for the host platform.
- Bare-metal runtime builds disable IREE thread creation, file I/O, and blocking wait support, while keeping synchronization enabled through the local critical-section shim.
